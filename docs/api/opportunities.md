# Opportunities API

Base URL (development): `http://localhost:5000/api`

The canonical machine-readable spec is generated by the backend at
`/openapi/v1.json` (development only). This file records the contract that the
Angular and Flutter clients code against.

---

## `GET /api/opportunities`

Returns every published volunteering opportunity, ordered by start date
(soonest first).

**Authentication:** none (public read).

### Response `200 OK`

```json
[
  {
    "id": "2",
    "title": "Website Accessibility Audit",
    "description": "Review a small charity site against WCAG 2.1 AA and write up findings.",
    "location": "Remote",
    "isRemote": true,
    "startsAtUtc": "2026-09-21T12:00:00Z"
  }
]
```

| Field | Type | Notes |
|---|---|---|
| `id` | `string` | Stable identifier. Will be a MongoDB `ObjectId` string once persistence lands. |
| `title` | `string` | Never empty. |
| `description` | `string` | Never empty. |
| `location` | `string` | May be empty for remote opportunities. |
| `isRemote` | `boolean` | |
| `startsAtUtc` | `string` | ISO-8601, always UTC. |

An empty result set returns `200 OK` with `[]`, not `404`.

### Errors

All failures use RFC 7807 Problem Details with content type
`application/problem+json`:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.6.1",
  "title": "An unexpected error occurred.",
  "status": 500,
  "instance": "/api/opportunities",
  "traceId": "0HN7GJ2K8QVQR:00000001"
}
```

Validation failures additionally carry an `errors` map of field name to
messages. Clients read `detail`, then `title`, then fall back to the status
code — see `errorNormalizationInterceptor` in the Angular app.

## Searching

Search is not a `GET` on this resource. It runs as a background job submitted to
`POST /api/jobs/opportunity-search`, with results pushed over the WebSocket —
see [jobs.md](./jobs.md) and
[ADR 0001](../adr/0001-async-request-reply-over-websockets.md).

---

## `GET /health`

Liveness probe. Returns `200 OK` with `{ "status": "healthy" }`.

---

## Not yet implemented

The PRD models `Opportunity` with `org_id`, `skills_needed[]`, `capacity`,
`end_date` and `status`. Those fields are deliberately absent until the
features that need them are built. Adding them is additive and non-breaking.
